# Easy NCC — Flutter + Supabase

**Phase 1 source project** for BNCC Activity, Cadet and Training Management.

- Android + Web from one Flutter codebase
- Supabase Auth + PostgreSQL + Row Level Security
- BNCC logo and green/gold brand palette
- Google Sans typography (Google Fonts runtime cache)
- Smooth scroll, responsive navigation and lightweight page transitions

## Important before running

This archive contains the application source, assets and Supabase schema. The Android/Web runner folders are generated by the Flutter SDK on the target PC so the project uses the exact Gradle and web bootstrap templates installed with that SDK.

Use **Flutter 3.47+ / Dart 3.13+** and Java 17. In the extracted project root, run:

```bash
flutter create --platforms=android,web --org com.easyncc --project-name easy_ncc .
flutter pub get
```

The `flutter create` command generates the Android runner files and refreshes the platform scaffolding. Keep the existing `lib/`, `assets/` and `supabase/` folders unchanged if Flutter asks about overwriting files. The branded `web/` folder is already included in this archive. After platform generation, run `flutter pub get`.

## 1. Run the demo preview

If you have not configured Supabase yet:

```bash
flutter run -d chrome
```

or run on a connected Android phone:

```bash

```

The app opens a setup screen. Select **Demo Preview** to explore the UI. Demo data is held in memory only and is not synced to Supabase.

## 2. Configure Supabase (one time)

1. Create or open your Supabase project.
2. Open **SQL Editor** in the Supabase Dashboard.
3. Paste and run the complete file `supabase/schema.sql`.
4. Open `lib/core/app_config.dart`.
5. Replace `YOUR_PROJECT_REF` in `supabaseUrl` with your Project URL, and replace `YOUR_SUPABASE_PUBLISHABLE_KEY` with the **Publishable key** from Project Settings → API Keys.
6. Save `app_config.dart`. This is a one-time configuration; normal run and build commands do not need credentials in the command line.

Example configuration in `lib/core/app_config.dart`:

```dart
static const String supabaseUrl = 'https://YOUR_PROJECT_REF.supabase.co';
static const String supabasePublishableKey = 'YOUR_SUPABASE_PUBLISHABLE_KEY';
```

## 3. Create the first Admin

New registrations are automatically created with the `member` role. This is intentional; users cannot promote themselves.

1. Register through Easy NCC and complete email verification if enabled in Supabase Auth.
2. In Supabase Dashboard → Authentication → Users, copy that account's UUID.
3. Run this in SQL Editor:

```sql
update public.profiles
set role = 'admin'
where id = 'PASTE-AUTH-USER-UUID-HERE';
```

4. Log out and log in again. The Admin role will be loaded from `profiles`.
5. The Admin can promote another account to Supervisor and assign Cadets from the Cadet Directory page.

## 4. Public Central Activities

- Personal activities are visible only to their owner (and Admin).
- Central activities are readable by anonymous visitors on the Internet.
- A signed-in user can create a Central activity.
- Only the owner or Admin can edit/delete an activity.
- Event notes inherit the parent's visibility. Do not put private or sensitive information in a Central activity or its notes.
- Public Central activities show the display name, never the account email.

## 5. Google Sans and Bengali text

The app requests **Google Sans** through `GoogleFonts.getTextTheme` and `GoogleFonts.getFont` from `google_fonts: ^8.2.1`. This version keeps the package API compatible with Flutter's Material `TextTheme`; version 9 migrated its Lite API to `material_ui`, which caused the type mismatch reported during the first run. The font is downloaded on first use and cached by the package. An Internet connection is needed the first time; the system font is used as fallback if the font cannot load. Bengali glyphs use the device/browser Bengali fallback fonts.

A4 measurement PDF uses Noto Sans Bengali via `PdfGoogleFonts`. The first PDF export may need Internet access to load/cache the font.

## 8. Security notes

- Never put a Supabase `service_role` / secret key in Flutter code or build arguments.
- Use only the Project URL and Publishable key in the client.
- The SQL schema enables RLS on every application table.
- Admin role changes are protected by a database trigger and RLS.
- Measurement and training data are not public.
- Test RLS using separate Member, Supervisor and Admin accounts before production use.

## 9. Current implementation notes

- Demo Preview is in-memory and resets when the app is restarted.
- Supabase features become live only after the schema is applied and valid credentials are supplied.
- PDF font retrieval requires Internet access on first use.
- The source archive was generated without a Flutter SDK in the build environment. Run `flutter pub get`, `flutter analyze` and the Android/Web build commands on your PC to complete environment-level verification. The `setup_windows.bat` helper is intentionally not included; run the two setup commands manually.
